## 三、问题清单

### 严重 1｜business（业务端）科目可见范围被放宽，与「只收窄」的设计声明不符

- **复现（数据层，已实跑）**
  ```js
  P.state.dataView = 'business';
  P.visibleSubjects().length        // 19  ← 改造前的名称白名单
  P.visibleSubjectCodes().length    // 162 ← 现在放行的编码数
  P.canSeeSubjectCode('6602010101') // true  ← 改造前按名称「平台佣金」判定为 false
  ```
  多出的 143 个编码全部由 `visibleSubjectCodes()` / `canSeeSubjectCode()` 的
  `s.path[0] 命中白名单即放行` 规则产生：**销售费用 140 个 + 综合税负 3 个**。
- **成因（读码）**：`js/core.js:443-469`。区间白名单取自旧的 43 条平铺名称，`销售费用`、`综合税负` 恰在区间内，于是其**全部子孙科目**（平台佣金、站内广告、物流费用明细、680101–680103 等）被连带放行；注释写的是「拿不准一律判不可见，绝不因新编码而放宽权限」，与实现相反。
- **影响**
  - 已实测**暂无金额泄露**：M3 的 `sourceRows()` 先经名称口径的 `P.applyDataView()`，`6602010101` 的单元格为 0（D22i2）。
  - 但 M3 的 `visibleTemplate()` 直接用 `canSeeSubjectCode()`，**业务端看到的模板行数从 19 行变为 162 行**，等于暴露了费用明细的科目结构；任何将来直接用 `canSeeSubjectCode`/`visibleSubjectCodes` 过滤金额的调用点（报表导出、新模块）都会变成真实越权。
  - M5 页面展示的仍是名称口径 19 项，两套口径已经不一致。
- **建议**：path[0] 放行改为「仅当白名单明确包含该子科目，或存在显式父子授权映射」；否则直接回退到名称白名单。

### 中等 2｜M2「提问」点击后无结果且不可再提问（**既有缺陷，非本次改动引入**）

- **复现（已实跑 2 次，headless）**：加载 M2、在 `#m2-question` 输入任意问题、点 `#m2-ask` →
  `#m2-status` 永久停留「AI 正在理解问题并生成 SQL…」，`.turn` 数量 0，`#m2-turns` 仍是空态，无错误提示；再次点击提问无任何反应（`busy` 未复位）。
- **成因（读码推断）**：`js/modules/m2.js:220-224` 在 `try` **之前**执行 `turns.push(t); render(currentRoot);`，此时 `t.plan` 仍为 `null`，而 `turnHtml()` 直接读 `t.plan.sql` → 抛错；因异常发生在 `try` 之外，`finally { busy = false }` 不执行，模块被永久锁死。
- **归属**：`git diff 6442ae7 HEAD -- js/modules/m2.js` 为空 → 与本次 M3 改动无关，属已有代码。本次验证**未捕获到 `window.onerror`/`unhandledrejection`**（原因未确认），机制结论属读码推断；但「点击后无结果 + 无法再次提问」的运行现象稳定复现。
- **影响**：M2 全部功能不可用；建议开发者单独修复并加一条「提问首帧」回归断言。

### 中等 3｜M2 月份筛选口径与数据口径不一致（读码 + 局部执行证据）

- `heuristicPlan()` 生成 `{field:'month', value:'1月'}`（`js/modules/m2.js:141`），`P.matchFilter` 对维度做字符串全等比较。
- 实测：`matchFilter({month:'2026-01'}, {field:'month',value:'1月'}) === false`；`{month:'1月'}` → `true`。
- 影响：带年份的导入数据（`2026-01`）下，「2026年1月」这类问题会返回空集；改造前用 `period='2026-01'` 是能命中的。当前被问题 2 掩盖。

### 轻微 4｜旧 4 位编码在新模板中含义变化（已提示，但需业务确认）

`4101` 旧义「销售费用」→ 新义「产品毛利-内核法」，导入时会写 `subject_code=4101`、名称取「产品毛利-内核法」并给出「编码新旧含义不同，请核对数据口径」提示（D21d 实跑通过）。若历史数据集里存有 4 位编码，金额会被归到新科目行，需业务侧确认清洗口径。

### 轻微 5｜M2 侧栏字段说明过期

`js/modules/m2.js:56` 仍写「维度：期间、区域、产品线、渠道」，与现用维度（月份/站点/平台/渠道/…）不一致，会误导提问者。

### 观察（不计为缺陷）

- 全不选时矩阵/管报仍输出 201 行，矩阵在 0 个月份列时只剩科目列与编码列；管报与矩阵均已补「模板 N 行全部为 0」提示（工作区最新 `view.js` 实跑：201 行 + 提示文案）。可读性一般，但语义正确（无匹配 ≠ 空白页）。
