## 0.000 v0.13 占比列（2026-11-18 15:10）

**需求**：报表同行数据旁新增百分比项目，定义为「该科目占销售收入的比例」，可手动选择是否展示，版式参考《40103.png》。

**实现**

| 项 | 说明 |
|---|---|
| 位置 | 管报、经营分析两个视图；每个期间（月份）旁紧跟一列「占比」 |
| 表头 | 管报：第一行期间 `colspan=2`，第二行「实际数 / 占比」；经营分析：月份列后直接跟「占比」 |
| 计算 | 占比 = 该行该期间金额 ÷ **同期销售收入**（`6001` 含下级汇总） |
| 单位 | 只有金额科目计算；数量（订单量/销量）、人数显示「—」，不与金额混算 |
| 开关 | 工具条圆角勾选框「显示占比」，默认开；状态随看板保存（`filters_json.showPct`） |
| 分母缺失 | 当前数据视图看不到 `6001` 时不拿别的科目顶替，全部显示「—」并在工具条给橙色提示 |

**验证数值（固定样本）**

| 科目 | 2026-01 | 2026-02 | 2026-10 |
|---|---|---|---|
| 销售收入 6001 | 120.00 / **100.0%** | 80.00 / **100.0%** | 60.00 / **100.0%** |
| 销售费用 6602 | -30.00 / **-25.0%** | -8.00 / **-10.0%** | 0 / 0.0% |
| 订单量 1001（数量） | 12 / **—** | 0 / **—** | 0 / **—** |

**顺带修掉的持久化缺陷**：`saveState()` 之前没有写入 `levelFilter`，导致 v0.12 声称的「层级勾选随看板保存」实际未生效（重开看板会回到默认四级全选）。本次一并补上 `levelFilter` 与 `showPct`。

> 口径说明：占比的分母是**同期**销售收入，不是全年收入；跨期间不可比较。
> 负数占比保留负号（如成本、费用类科目为负值时显示 -25.0%），不做绝对值处理。


## 0.00 v0.12.2 层级勾选修复（2026-11-18 14:40）

| # | 问题 | 根因 | 处理 |
|---|---|---|---|
| 1 | 勾二级时仍显示三四级科目列 | 列在 `renderReport` / `renderAnalysis` 里写死 4 列 | 科目列改为按**最高勾选级**动态生成（`leadLevels()`）：勾二级 → 一级+二级+编码 3 列，三重四级列不渲染；左偏移由 `syncSticky` 按实际列宽测量 |
| 2 | 一级科目勾不掉 | ① `engine.normalizeLevels([])` 返回 `null`（=不限制）② `view.bindRail` 强制「勾 N 就回填 1..N」 | ① 空数组现返回 `[]`，表示一行都不显示；只有 `null/undefined` 才是「不限制」② `bindRail` 改为每个复选框独立上报，不再补选 |
| 3 | 全不勾时应为空白 | 同上，空数组被当成「全部」 | 勾选栏保留、主区域显示「未勾选任何科目层级，报表为空白」，可随时重新勾上 |

**当前语义（管报 / 经营分析）**

| 操作 | 行 | 科目列 |
|---|---|---|
| 四级全选（默认） | 211 | 一~四级 + 编码（5 列） |
| 只勾一级 | 21 | 一级 + 编码（2 列） |
| 只勾二级 | 39 | 一级、二级 + 编码（3 列） |
| 只勾三级 | 56 | 一~三级 + 编码（4 列） |
| 勾 2、3、4（取消一级） | 190 | 一~四级 + 编码（5 列，一级行不出现） |
| 全不勾 | 0 | 无表格，显示空白提示 |

> 口径不变：勾选层级只决定「显示哪些行/列」，金额仍由 engine 的 `rollup` 口径计算，
> 父级行永远是其自身 + 同单位子孙的合计，不会因为取消上级而改变数值。
> 列的收窄只是隐藏，不改变任何一行的数值。


## 0.0 v0.12.1 口径收紧（2026-11-18 下午）

| # | 问题 | 处理 |
|---|---|---|
| 1 | 旧 4 位编码仍在用（1101/2101…），与新编码并存 | **旧编码一律停用**：`aliasesMap` 只保留 211 条新编码；旧编码导入时判未知并提示「旧版科目编码已停用，请用新编码重新导入」；`resolveSubjectValue` 不再按旧名称回退 |

> - **历史数据集若没有 `subject_code`，接上后报表会是全 0 并报 `missing_code`**，这是有意为之——请用新版模板（科目编码列）重新导入，或先补编码。
> - 旧编码（1101/2101/4201…共 32 个）不再解析，导入时直接报错，不做静默兼容。

## 1. 实现内容与修改文件

### 1.1 需求一：业务维度多选

| 项 | 实现 |
|---|---|
| 多选维度 | 月份、数据类型、站点/国家、平台、渠道、素材来源、品牌、品类、报表产品、科目，以及数据中仍存在的旧维度（区域、产品线） |

| 首次生成修复 | 一键生成模板后重建组件容器，解决首次点模板无图表的问题 |

### 1.2 需求二：科目月度对比

- 行 = 科目（模板顺序），列 = 年月 × 数据类型；不同数据类型**分列**，金额不相加。
- **v0.11 变更**：数据类型只保留「实际数」。预算数据颗粒度不足，暂不纳入 M3，也不做预算/实际对比；
  开关为 `js/modules/m3.js` 的 `HIDDEN_DATA_TYPES = ['预算数']`，恢复时改为 `[]` 即可。
- 列按年月升序（1 月 → 2 月 → 10 月），同月内数据类型顺序固定。
- 用户选中的月份即使没有明细也保留列并显示 0；不会凭空生成未选月份。
- 金额按整数分累加再还原，负数保留原符号；缺失组合补 0。
- 支持选择科目查看趋势图；**数量/人数科目不与金额同轴**，默认排除并提示排除数量。

### 1.3 需求三：管报预览

- 严格使用《管报格式.xlsx》201 条科目，含编码、层级、完整路径、模板顺序。
- 版式为「一级 / 二级 / 三级 / 四级科目 + 科目编码 + 月份数值列」，表头与左侧科目列冻结，可横向滚动。
- 模板行全部保留（默认 201 行），无匹配数据的有效科目单元格显示数值 0；无数据行淡显但不隐藏。
- 与矩阵、图表共用同一份筛选状态与同一份计算结果（`buildMonthlyMatrix` 只算一次）。
- 元信息条展示数据来源、期间范围、数据类型、生成时间、单位说明与口径提示；诊断异常单独警示。

### 1.2 需求二：科目月度对比

- 行 = 科目（模板顺序），列 = 年月 × 数据类型；不同数据类型**分列**，金额不相加。
- **v0.11 变更**：数据类型只保留「实际数」。预算数据颗粒度不足，暂不纳入 M3，也不做预算/实际对比；
  开关为 `js/modules/m3.js` 的 `HIDDEN_DATA_TYPES = ['预算数']`，恢复时改为 `[]` 即可。
- 列按年月升序（1 月 → 2 月 → 10 月），同月内数据类型顺序固定。
- 用户选中的月份即使没有明细也保留列并显示 0；不会凭空生成未选月份。
- 金额按整数分累加再还原，负数保留原符号；缺失组合补 0。
- 支持选择科目查看趋势图；**数量/人数科目不与金额同轴**，默认排除并提示排除数量。

### 1.3 需求三：管报预览

- 严格使用《管报格式.xlsx》201 条科目，含编码、层级、完整路径、模板顺序。
- 版式为「一级 / 二级 / 三级 / 四级科目 + 科目编码 + 月份数值列」，表头与左侧科目列冻结，可横向滚动。
- 模板行全部保留（默认 201 行），无匹配数据的有效科目单元格显示数值 0；无数据行淡显但不隐藏。
- 与矩阵、图表共用同一份筛选状态与同一份计算结果（`buildMonthlyMatrix` 只算一次）。
- 元信息条展示数据来源、期间范围、数据类型、生成时间、单位说明与口径提示；诊断异常单独警示。

## 9. v0.12 口径、差异与限制

### 9.1 父级汇总口径（新增）

- 管报与经营分析使用 `subjectRule='rollup'`：**父级 = 自身导入额 + 其下所有子孙编码的导入额**。
- 汇总按编码前缀判定（子编码以父编码开头且更长），不依赖名称，同名不同编码不会互相并入。
- **只在同一单位内相加**：`管理费用(6601)` 下面挂着 `人数(660101, headcount)`，
  金额汇总时排除它，并在报表顶部给出黄色提示。
  - 因此本系统 `管理费用` 与 Excel《经营分析报表》by月份 的合计会相差一个「人数」。
    例：Excel 管理费用 4,059,388 = 人工 3,078,327 + 其他 980,870 + 人数 **191**；
    本系统显示 4,059,197，不含 191。这是**有意为之**，人数与金额不同量纲。
- 科目月度对比（矩阵视图）仍保持 `direct`（只看本级导入结果），在顶部口径说明里标明，
  两种口径不会混在同一张表里。
- 仍未内置毛利/营业利润/净利润公式：这几行只是各自编码的导入结果，等级勾选后会含下级，
  但**不会**用收入减成本算出来。

### 9.2 占销售收入比

- 分母固定取 `6001 销售收入` 在当前筛选条件下的合计（含其下级 600011~600104）。
- 仅金额科目计算占比；数量（订单量/销量）与人数一律显示「—」。
- 《经营分析报表》by月份 右侧那组「值2」列对销量行是**平均单价**（收入÷销量），
  本系统**未实现**该指标——单价不属于科目金额，需业务先定义口径。

### 9.3 模板结构异常（1 条）

- `680103`：编码 6 位（二级），但路径文字是 3 段
  （综合税负 / 进口成本预缴增值税 / 印尼正清增值税）。
  按「层级由编码位数决定」的规则判为**二级**，名称取「进口成本预缴增值税」，
  「印尼正清增值税」存为备用名。管报里该行会占 3 个科目列，属已知展示特例。

### 9.4 与《经营分析报表》by月份 的实际差异

| 项 | Excel 原表 | 本系统 | 原因 |
|---|---|---|---|
| 月份范围 | 3月~10月（无年份） | 由筛选决定，带年份时显示 2026-03 | 原表无年份，系统不臆造年份 |
| 管理费用 | 含 191 人数 | 不含人数 | 不同量纲不混加 |
| 销量行第二组值 | 平均单价 22.62 | 显示「—」 | 单价口径未定义 |
| 占比列 | 值2（各行列含义不完全一致） | 统一「占销售收入」 | 口径必须唯一可解释 |
| 科目编码列 | 无 | 有 | 便于财务核对与追溯 |
