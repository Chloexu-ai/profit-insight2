# 利润分析平台 · Profit Insight

一个可供多人协作开发的纯前端利润分析平台，四个模块独立运作、共享同一套数据契约与云端协作空间。

## 模块结构

| 模块 | 文件 | 职责 |
|------|------|------|
| M1 数据导入工作台 | `js/modules/m1.js` | 管报模板下载（**科目用编码**）、CSV/Excel 解析清洗、主数据规范化、字段映射、校验入库；科目编码自动转汉字显示 |
| M2 Text to SQL 智能问数 | `js/modules/m2.js` | 自然语言 → 只读 SQL 计划 → 执行 → 归因，含本地规则降级；受数据视图权限约束 |
| M3 数据看板 | `js/modules/m3.js` | 管报看数模板、KPI/柱/线/饼/表、**多选筛选器**、拖拽布局；受数据视图权限约束 |
| M4 信息推送 | `js/modules/m4.js` | 触发条件、定时规则、推送记录；受数据视图权限约束 |
| M5 数据权限中心 | `js/modules/m5.js` | 管理层/业务端两级视图，按科目可见范围隔离阅读与查询；成员视图分配、本会话视图切换预览 |
| M6 主数据维护 | `js/modules/m6.js` | 在线维护各维度枚举、别名与科目编码，保存到云端按空间隔离，M1/M2/M3 自动跟随 |
| 共享底座 | `js/core.js` `js/config.js` `js/app.js` | 云 SDK 客户端、登录、模块注册表、数据清洗聚合、数据字典、数据视图引擎 |

每个模块通过 `window.PA{M1..M4}.mount(el)` / `destroy()` 独立挂载，互不干扰。

## 数据契约（管报主数据）

`js/config.js` 里的 `PA_DICT` / `PA_MEASURES` / `PA_DIM_LABELS` 是 M1–M4 共用的字段字典，**新增指标或维度请先改这里**，保持四个模块口径一致。字典依据《管报主数据及定义.xlsx》构建。

**标准导入模板表头**（`PA_TEMPLATE_HEADERS`）：
`月份 | 数据类型 | 站点/国家 | 平台 | 渠道 | 素材来源 | 品牌 | 品类 | 报表产品 | 科目 | 金额`

**十大维度**：
- 月份（1–12 月）、数据类型（实际数 / 预算数 / 预测数，编码 T01/T02/T03）
- 站点/国家（ID/MY/PH/TH/VN/SG/US/MX/BR/GE/FR，C01–C11；德国 DE 统一为 GE）
- 平台（Tiktok/Shopee/Lazada/Amazon/线下，A01–A04）、渠道（33 项，S01–S33）、素材来源
- 品牌（GMEELAN/GLOSTAR/HAIRTIFIC/YOUNJOY/TOOTHGEEK/非自营品牌）、品类（底妆/美白祛斑/清洁）、报表产品（65 项）、科目（四级科目树）

**主数据自动规范化**：导入时编码（C10/S33/T02）、别名（德国、速卖通、tiktok）、大小写都会转为标准值，见各维度的 `aliasesMap`。

**金额归集口径**：按「科目 + 数据类型」把金额自动归集为实际收入 / 实际成本 / 预算收入 / 预算成本（规则见 `PA_DICT.subjectRole` 与 `dataTypeRole`），因此管报格式与旧指标口径可共存。

派生指标：实际利润、预算利润、利润差异、收入差异、利润率。旧格式（期间/区域/产品线/收入/成本/预算）仍可导入，字段自动兼容。

**科目编码录入**：科目维度带稳定数字编码（`subject.codes`，如 1101=销售收入、2101=产品成本-内核法、3102=销售毛利-内核法、5102=净利润-内核法）。M1 模板「科目编码」列按编码录入，上传后通过 `aliasesMap` 自动转为标准汉字名称展示与入库；旧汉字模板仍可导入。编码对照可下载「科目编码表」。

**数据视图权限**（M5）：`PA_DATA_VIEWS` 定义两级视图——管理层可见全部科目（含真实成本到净利润），业务端仅可见「产品成本-内核法 → 销售毛利-内核法」区间。所有模块经 `PA.applyDataView()` 统一过滤，控制的是**应用内阅读/查询范围**；强安全隔离需将敏感科目拆为独立数据集并配合服务端 RLS。成员默认视图由角色决定（`PA_ROLE_VIEW`），可在 M5 单独指定并存于 `pa_members.data_view`。

**主数据在线维护**（M6）：维度枚举/别名/科目编码可在界面编辑，写入云端 `pa_masterdata`（按空间隔离，仅所有者可保存），加载时覆盖系统默认字典，改动即时影响 M1/M2/M3。

**完整口径文档**：[`docs/管报主数据口径.md`](docs/管报主数据口径.md) —— 含全部维度的标准取值、科目编码对照、别名对照、指标字典、`amount` 归集规则、数据视图权限与示例数据。该文档由脚本从代码字典自动生成；若修改了 `js/config.js` 的维度或指标，请在项目根目录运行 `node tools/gen-masterdata-doc.js` 同步文档，避免口径脱节。

## 本地运行

纯静态站点，无需构建、无本地依赖。任选一种：

- 直接双击 `index.html`（部分浏览器对本地文件有限制）；
- 推荐：`python -m http.server 8000`，浏览器打开 `http://localhost:8000`。

登录使用手机号验证码；微信登录需发布到 HTTPS 域名后可用。

## 云端环境

`js/config.js` 中的 `endpoint` / `oauthRelayBaseUrl` / `publishableKey` 指向本项目已开通的云服务（数据库、Auth、LLM）。这是**公开配置**（publishable key），可提交到仓库。数据存在云端，协作者共享同一后端。

## 协作开发流程（Git）

本项目采用「分支开发 + PR 合并」方式，避免互相覆盖。

```bash
# 1. 克隆仓库
git clone <仓库地址>
cd <项目目录>

# 2. 新建分支（按你的任务命名）
git checkout -b feature/m3-add-yoy-chart

# 3. 修改代码后提交
git add .
git commit -m "M3 增加同比柱图"

# 4. 推送分支
git push -u origin feature/m3-add-yoy-chart
```

然后在代码平台（CNB / GitHub / Gitee）上创建 Pull Request，由负责人 review 后合并到 `main`。

### 用 WorkBuddy 协作改代码

成员可在 WorkBuddy 新建任务时「选择工作空间」指向本仓库目录，然后用自然语言提需求，例如「给 M3 加一个环比折线图」「把主题改成深色」，WorkBuddy 会基于同一份代码修改。改完同样走分支 + PR 提交。

### 分工建议

- 负责人：main 分支合并、M1 数据口径、M4 推送规则、云端数据表与权限。
- 协作者：各自认领 M2 问数场景、M3 看板组件等，建独立分支。

## 注意事项

- 改页面**内容**（数据/看板/规则）不需要改代码：登录应用 → 同一协作空间 → 编辑成员直接操作即可。
- 改页面**代码**（布局/样式/新模块）才需要走上面的 Git 流程，且合并后需重新发布应用才会在线上生效。
- 新增模块：复制任一 `js/modules/mN.js`，在 `js/app.js` 注册导航，在 `index.html` 引入脚本即可，不影响现有模块。
- `.workbuddy/`（本地工作区数据）和 `*.genie`（本机应用卡片，含绝对路径）已在 `.gitignore` 中排除，不要提交。
