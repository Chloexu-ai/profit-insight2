## 1. 实现内容与修改文件

### 1.1 需求一：业务维度多选

| 项 | 实现 |
|---|---|
| 多选维度 | 月份、数据类型、站点/国家、平台、渠道、素材来源、品牌、品类、报表产品、科目，以及数据中仍存在的旧维度（区域、产品线） |
| 单选保留 | 数据源选择器、已保存看板选择器保持单选 |
| 语义 | 同维度 OR、跨维度 AND；维度未出现 = 全部；空数组 = 全不选（返回无匹配，不退回全部） |
| 操作 | 搜索、勾选、全选（搜索时只作用于可见结果）、全不选、重置；触发器显示已选数量 |
| 期间归一 | `month` 与 `period` 合并为「月份」一个入口，旧配置里的 `1月` 写法自动转成期间 key |
| 状态持久化 | 数据源、筛选、视图一并写入 `filters_json`（version 2），重绘不再回落到「全部数据集」 |
| 空间隔离 | 切换空间时清空 `current`、搜索态与已选科目，不残留上一空间状态 |
| 首次生成修复 | 一键生成模板后重建组件容器，解决首次点模板无图表的问题 |

### 1.2 需求二：科目月度对比

- 行 = 科目（模板顺序），列 = 年月 × 数据类型；实际数 / 预算数 / 预测数**分列**，金额不相加。
- 列按年月升序（1 月 → 2 月 → 10 月），同月内数据类型顺序固定。
- 用户选中的月份即使没有明细也保留列并显示 0；不会凭空生成未选月份。
- 金额按整数分累加再还原，负数保留原符号；缺失组合补 0。
- 支持选择科目查看趋势图；**数量/人数科目不与金额同轴**，默认排除并提示排除数量。

### 1.3 需求三：管报预览

- 严格使用《管报格式.xlsx》201 条科目，含编码、层级、完整路径、模板顺序。
- 版式为「一级 / 二级 / 三级 / 四级科目 + 科目编码 + 月份数值列」，表头与左侧科目列冻结，可横向滚动。
- 模板行全部保留（默认 201 行），无匹配数据的有效科目单元格显示数值 0；无数据行淡显但不隐藏。
- 与矩阵、图表共用同一份筛选状态与同一份计算结果（`buildMonthlyMatrix` 只算一次）。
- 元信息条展示数据来源、期间范围、数据类型、生成时间、单位说明与口径提示；诊断异常单独警示。

## 5. 未确认的财务口径与假设

以下均为**当前实现的显式假设**，不是已确认口径，需财务确认后才能定稿：

1. **每月累计**：按月内发生额合计实现，**未实现年初累计 YTD**。
2. **毛利/营业利润/净利润**：模板未给公式，当前仅按对应编码汇总已导入结果；无数据为 0，界面上标注为「导入结果口径」。
3. **父子同存**：按本级编码直接汇总，**不把父级与子级相加**；未做明细去重或覆盖判断。
4. **非金额指标**：订单量、销量可按月求和；人数跨月累计规则未确认，当前只做月内合计，且不与金额同轴或混加。
5. **币种**：假设导入前已统一币种，系统不做汇率换算，也不把不同本币相加。
6. **报表产品**：`report_product` 仍不等于独立 SKU，本期未做 SKU 粒度建模。

## 6. 已知限制与风险

1. **旧编码冲突（需人工确认）**：旧字典 `4101/4102/4103` 分别是「销售费用 / 线上货架站内推广费用 / 线上货架站外推广费用」，
   新模板 `4101/4102/4103` 是「产品毛利 / 销售毛利 / 前台毛利」。导入映射会给出告警，但历史上以编码写入的数据存在被重新解读的风险。
2. **42 个重名科目**：如「平台佣金」「业务招待费」「广告费 - 赠款」「bu前台」等，按**名称**归集必然歧义。
   新导入请使用「科目编码」列或完整路径；歧义行不会静默归集，会计入 diagnostics 并在界面警示。
3. **受限视图**：业务端视图仍沿用旧的名称白名单映射到 201 模板，结果是**少显示**（宁可少看也不放宽），
   如需按新模板精确授权，应由负责人在 M5 重新定义科目范围。
4. **期间**：无年份的「1月」保持独立域（`LEGACY-M01`），不会并入任何年份，也不与 `2026-01` 合并。
5. **Excel 导出未实现**：按要求作为配套功能单独评估，本次未做导出，因此也不存在「已实现导出」的验证记录。
6. **未验证项**：
   - 真实云端数据的读写与保存恢复（需要登录态与生产库）
   - 跨协作空间切换的端到端行为（代码已处理，但未在真实多点数据下跑通）
   - 只读成员的操作受限（依赖云端 RLS，本地无法模拟）
   - 用户真实《管报格式.xlsx》导入后的编码回填（仅用 CSV 固化的 201 条做过比对）
